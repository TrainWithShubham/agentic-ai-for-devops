# Course development

Work on `v2`. Keep commits short. Do not add co-author trailers, push to GitHub, create a PR, merge, or change `main` unless the user asks.

Use plain professional writing. Gada Electronics characters belong in the fictional incident and sample identities; keep technical names descriptive. Avoid slogans, repeated summaries, and inflated production claims.

Run commands with uv and the committed lockfile. Keep learner access free through individual OpenRouter keys. Never silently choose paid inference or distribute the instructor's AWS credentials. Offline practice must remain clearly labeled.

Do not commit `.env`, `.state`, keys, tokens, or private signing material. Keep V1 code on the `v1` branch only. Do not restore legacy modules or their requirements file to `v2`. Tests must check meaningful outcomes, especially access filtering, approval integrity, restart/resume, and idempotency.

Record architecture choices, failures, fixes, and verification limits in `DECISIONS.md`. Describe AWS features as live only after invoking and verifying them.
