# Working glossary

| Term | Meaning in this course |
|---|---|
| LLM | A language model that produces a response from supplied context |
| Token | A unit used to represent model input/output; not always a complete word |
| Context window | The input/output capacity of one model request |
| Context engineering | Choosing and maintaining the instructions, evidence, state and tool results supplied to a model |
| System prompt | Application-owned instructions for the model's task and response |
| Structured output | A response shaped to a schema; its facts still need verification |
| Workflow | Steps and transitions chosen by application logic |
| Agent | A loop in which a model can choose permitted next steps using observations |
| Tool calling | A model requests a named operation with arguments; software validates and executes it |
| MCP | A protocol through which clients discover and use server capabilities such as tools |
| RAG | Retrieving external evidence and supplying it as context for answer generation |
| Embedding | A numeric representation used to compare items such as text by similarity |
| Chunk | A bounded part of a source document with its identifying metadata |
| RBAC | Authorization rules based on trusted roles |
| OAuth | A framework for delegated API access |
| OIDC | An identity layer built on OAuth 2.0 |
| HITL | Human-in-the-loop: a person participates in a decision or action boundary |
| Checkpoint | Saved execution state used to inspect or resume work |
| Harness | Software around the agent loop that manages execution and controls |
| Evaluation | Checking behavior against explicit expected outcomes |
| Idempotency | Repeating an operation does not repeat its side effect |
| Runtime | The environment executing the application code |

See the [syllabus](CURRICULUM.md) for how these concepts fit together.
